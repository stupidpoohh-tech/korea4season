# 검증 하네스

지도가 계절을 제대로 말하고 있는지 **화면에서** 확인한다.
typecheck 와 build 가 통과하는 것은 완료 조건이 아니다
(IMPLEMENTATION_RULES §12).

여기 있는 검사는 전부 **실제로 한 번씩 깨졌던 것**이다. 새 기능을 넣을
때마다 같은 자리가 다시 무너지므로, 고칠 때 쓴 측정을 그대로 남겨 둔다.

## 쓰는 법

두 가지가 먼저 떠 있어야 한다.

1. 프로덕션 빌드 서버 — `npm run build` 뒤 `npx next start -p 3031`
   (개발 서버로 재면 성능 수치가 뜻이 없다)
2. 헤드리스 브라우저 — 없으면 스크립트가 알아서 띄운다

```
npm run verify              전부
npm run verify playback     이름이나 파일명 일부로 골라서
npm run verify:shot out/    대표 날짜 화면 찍기
```

주소와 브라우저는 환경변수로 바꾼다.

```
VERIFY_URL=http://localhost:3000   기본 http://localhost:3031
VERIFY_CDP=http://127.0.0.1:9222   기본값과 같다
CHROME_PATH=/path/to/chrome        직접 지정할 때
```

## 검사 목록

| 파일 | 무엇을 지키는가 | 왜 생겼는가 |
|---|---|---|
| `flower-stability.mjs` | 날짜를 넘겨도 같은 꽃이 같은 자리에 | 종의 자리를 밀도순 배열 순번에서 뽑아, 하루를 넘길 때마다 벚꽃이 튀었다 |
| `consistency.mjs` | 직접 선택 · 슬라이더 · 재생 뒤가 같은 화면 | 색을 끊는 폭을 '끄는 중' 인지에 따라 바꿔, 같은 날짜가 두 가지 색이었다 |
| `map-sprites.mjs` | 바다 생물이 육지로 올라가지 않는다 | 갈치가 제주도 한가운데 앉았다 |
| `viewports.mjs` | 한 화면에 담긴다 (넘침 0px) | 1px 이 넘쳐 스크롤바가 생기면 그만큼 지도가 깎인다 |
| `scrub.mjs` | 끄는 동안 주소를 몇 번 쓰는가 | Safari 의 replaceState 한도를 넘겨 iOS 에서 화면이 죽었다 |
| `playback.mjs` | 1년 재생 프레임 (CPU 4배 감속) | 시간 슬라이더가 이 제품의 핵심이다 |
| `heap.mjs` | 1년을 여덟 번 훑어도 쌓이지 않는다 | 프레임이 빠른 것보다 쌓이지 않는 것이 먼저다 |

## 기준값을 바꿀 때

각 파일 맨 위의 상수가 합격선이다 (`HISTORY_BUDGET`, `BUDGET_MEDIAN_MS`,
`LEAK_MB` 등). 값을 올려서 통과시키기 전에, 그 수치가 사용자에게 무엇을
뜻하는지 먼저 적어 두는 편이 좋다 — 한 번 올리면 되돌아오지 않는다.

## 여기서 못 재는 것

- **실기기.** 이 저장소 안에서는 WebKit 을 받을 수 없고 배포 주소도
  프록시에 막혀 있다. iOS 사고는 대리 지표(주소 갱신 횟수 · 힙)로만 본다.
- **색이 예쁜가.** `shot.mjs` 로 찍어 사람이 본다.
- **데이터가 맞는가.** 꽃 · 단풍 시기는 아직 `confidence: "demo"` 다.
